本書は、private authoringリポジトリ `gogyousisou/urban-assault-authoring` で行った外部シナリオ査読・標準フォーマット研究のうち、ユーザー承認済みの設計原則を公開側開発ブランチへ統合した記録です。

第三者シナリオの本文や固有データは公開側へ転載しません。公開側へ反映するのは、横断研究から得た抽象化された構造・査読原則と、URBAN ASSAULT独自のテンプレートだけです。

## 3. 統合した承認済み原則

### 3.1 d33

- 標準d33は9枠。
- 標準出目は11、12、13、21、22、23、31、32、33。
- 変則型を禁止しない。
- 変則型は使用する有効出目を明示する。

### 3.2 d66

- 十の位カテゴリを固定番号へ縛らない。
- 各シナリオがカテゴリIDと役割を宣言する。
- 重複、繰上げ、循環、候補枯渇、強制修正の処理順を必要に応じて明示する。

### 3.3 成功・失敗・終了

全シナリオで、次を客観的に判定できるよう分離して記載します。

- 任務目標
- 成功条件
- 失敗条件
- 終了条件

倫理的結末、公的説明、部分成功などを扱う場合は、客観的成否とは別の結果として管理します。

### 3.4 読み上げ文と処理

- 読み上げ文の長さは固定しない。
- 読み上げ／フレーバーとゲーム上の必須処理を分離する。
- 読み上げ文を省略しても、判定、対象、資源、状態更新、終了条件を処理できる状態を維持する。
- 必須数値や成功・失敗条件をフレーバーだけに埋め込まない。

### 3.5 Markdown本文とYAML台帳

編集正本はMarkdown本文とYAMLサイドカーの組み合わせです。

各イベントまたは独立処理単位で、次のいずれかを明示します。

- `ledger`：YAML台帳を処理正本とする。
- `prose`：文章と不可分な処理をMarkdown本文の正本とする。
- `mixed`：数値・ID等を台帳、文脈依存処理を本文の正本とし、担当範囲を分離する。

`prose`／`mixed`でも、本文アンカー、処理概要、成功・失敗、主要数値、参照IDなど、監査に必要な情報を台帳へ保持します。

PDF/TXTは生成成果物であり、PDFからMarkdown/YAMLへ逆同期しません。

## 4. 物語・イベント構造へ反映する原則

- プロローグは、舞台の日常、異変、当事者、プレイヤーが関与する理由、任務を接続する。
- 中間イベントは単に強敵を置く場所ではなく、状況またはプレイヤーの理解が変化する転換点として設計する。
- d33イベントは短いイベント単位で状況・異変・選択・結果・後半への接続を追跡できるようにする。
- d66ではカテゴリごとに役割を分担し、どの順序で出ても個々のイベントが処理可能な構造を目指す。
- 複数周回では「シナリオ段階」「挑戦回数」「世界状態」を同じ値として扱わない。
- 連続戦闘は読み上げ上の一場面と、処理上のフェーズを区別する。
- 勝利、敵撤退、分隊退却、交渉、捕虜・鹵獲、倫理的結果などを必要に応じて別項目で追跡する。
